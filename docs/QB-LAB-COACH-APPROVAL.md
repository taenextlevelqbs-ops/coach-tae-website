# QB LAB football-content approval register

All entries below are **DRAFT — NOT COACH APPROVED** as of 2026-10-23. No coaching review is inferred from code, citations, an owner's feature request, passing tests or a successful Preview. This is a review workflow and question register, not a completed curriculum or a claim of football realism.

Use only synthetic demonstration profiles. Open the linked QB LAB routes on the exact review commit's Preview; choose the named controls rather than relying on a diagram's appearance. Where a scenario is missing or a branch incomplete, the reviewer must record the gap, not approve a substitute. Existing legacy observations and the fixed-step live engine are distinct implementations.

## Approval workflow

1. **DRAFT:** Author records content ID/version, pathway, competition/rulebook/season, age/experience range, learning objective, authored assumptions, vocabulary, source/version, answer/explanation, actual engine assignments and known missing branches. Add deterministic replay/acceptance evidence and desktop/mobile screenshots where relevant.
2. **REVIEWED:** Coach Tae or a named qualified pathway reviewer plays the actual scenario, records exact commit/seed/configuration/inputs and observed result, checks each defender/receiver responsibility and answers the questions below. Record reviewer/date, requested corrections and applicable age/pathway. REVIEWED means examined; it is not approval.
3. **APPROVED:** An authorized reviewer explicitly accepts the corrected version and limitations for the recorded pathway/age/ruleset. Preserve the approval record and source evidence. Changed terminology, movement, assignments, question keys or rules returns the affected content to DRAFT. An approval for tackle does not approve flag or passing 7v7.

This workflow is documented but no publishing service or approval-status enforcement is connected. Existing content must remain presented as unreviewed synthetic instruction/demonstration. A future content registry should require an approval ID/version before inclusion in an approved curriculum or graded coach assignment.

Review record template:

```text
Content ID/version / title:
Status: DRAFT | REVIEWED | APPROVED
Pathway / governing ruleset / season / age / experience:

Source or rule section / system-dependent terms:
Expected coaching result / observed engine events and result:
Answer key and explanation / limitations / corrections:
Reviewer / review date / explicit approval or rejection:
Retest evidence / next review trigger:
```

## Review evidence and limits

Code/geometry/fixture verification establishes only the implementation facts it asserts. Record any disagreement between expected teaching behavior and engine behavior as an open defect; do not change a test solely to approve a misleading lesson. Reproducible inputs permit correction, not a claim of calibrated football physics.

The 2D engine is a simplified deterministic training model. Complete match systems, run fits, full protection communication, route-option rules, age-progressive curricula, dedicated girls flag lessons and a rigged 3D experience remain open unless separately implemented and reviewed. Source links and historical review context are in [Football review](QB-LAB-FOOTBALL-REVIEW.md); exact current gaps are in [Release audit](QB-LAB-RELEASE-GAP-AUDIT.md).

Coach approval cannot authorize real minor accounts or video uploads. Those require the independent owner, infrastructure and privacy gates in [Owner integration checklist](QB-LAB-OWNER-INTEGRATION-CHECKLIST.md).
