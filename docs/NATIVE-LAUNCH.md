# Native booking launch candidate — October 29, 2026

**Latest user instruction supersedes the earlier Calendly-preserving release.** Native booking is now the requested public journey. This candidate includes upstream commit `67330a7`; production launch is still held on real hosted acceptance, credentials and payment-mode restrictions. No production READY status is asserted.

## Implemented

- Homepage training cards and mobile/desktop booking buttons use `/book?kind=private` and `/book?kind=group`. Public fallback links/components are removed. A disabled or unconfigured platform displays a closed state rather than pretending booking works.
- Existing OTP, athlete registration, native availability, buffers, group capacity, training credits, coach dashboard, QB Lab and RLS remain in place. Earlier appointments are explicitly distinguished from website records.
- Paid-session holds remain unpaid until verified Stripe fulfillment. The existing durable outbox handles confirmations and reminders; production minute scheduling is prepared but not activated here.
- Checkout cancel URL carries the order UUID. The authenticated, same-origin `/api/platform/checkout/cancel` route queries only the current family's order. Stripe Checkout must be safely expired before an unpaid hold is released; ownership/customer/reference checks run **before** expiring anything. An incomplete server binding is refused for retry, not released optimistically. Already-closed orders are retry-safe, while payment-complete races are not cancelled.
- `checkout.session.expired`, `checkout.session.async_payment_failed`, and `payment_intent.payment_failed` now close eligible pending orders and release their holds. Failed-intent handling reads current Stripe state, validates order ownership, and expires an open Checkout first so its payment link cannot later sell released capacity. Add these events to the actual test webhook configuration when access exists; no hosted endpoint configuration has been changed.
- Migration `202610290006_checkout_closure.sql` adds cancelled/expired/failed order states and a service-only, transactional `ct_close_checkout`. It uses the same global schedule lock as booking, protects paid bookings and does not issue credits for unpaid cancellations. Late verified training payments for closed orders queue an idempotent refund instead of reviving a cancelled booking. A verified late-paid Lab order records payment normally; subscription access remains governed by current Stripe subscription state rather than inventing a booking refund.
- Stripe account identity is checked through `GET /v1/account` before price verification/new Checkout: credentials must belong to the supplied CoachTae account, preventing use of a different business's account. Existing live account/Price IDs/amounts remain unchanged; no duplicate products or accounts were created. Restricted credentials must have account-read access as well as their existing Checkout permissions.

## Reservation timing and migration safety

Checkout expires after 31 minutes from order creation; the existing reservation has a 35-minute hold. Signed expiry/failure events and verified cancellation release capacity earlier. Availability/capacity queries ignore elapsed holds even if maintenance has not marked the row expired. Closing a browser without returning is abandonment: expiry is required, not an instant browser-detection promise. Declined card payments terminate the old Checkout through the failed-intent workflow; parents may start a new reservation.

The existing protected busy-time import (migration 005) remains available. No Calendly appointment was deleted, changed or imported by this session. Before opening native booking, inspect/reconcile **every** upcoming/current legacy appointment, block its occupied coach time, and stop accepting new legacy bookings or establish a verified ongoing reconciliation workflow. A one-time import alone cannot protect against future bookings accepted by an independently open legacy calendar.

The production guard again applies to **all** production builds for this native-only candidate: native activation, exact-commit hosted-acceptance marker, verified project/origin, service bindings, strong cron secret and Stripe test mode are required. The marker has not been set and no guard was bypassed. An automatic unaccepted production build must not replace the working older site with a closed native booking page.

## Exact launch blockers

1. The runtime still has no bound Supabase/Stripe/Vercel/Resend service credentials or exposed service connectors. Existing GitHub repository transport works. Current enforced cloud configuration is revision 1 with no custom destination access; saved environment requirements/destination changes are an unpublished draft, not usable service access.
2. Actual live-site and Vercel API requests fail with proxy CONNECT 403. Consequently the actual schema/migrations, existing appointments, real OTP delivery/login, Stripe customer/price/account bindings, checkout/webhook delivery, production reminder ticks, runtime logs and deployment permissions cannot be inspected or tested here. No hosted migration was applied and no production promotion was performed. Existing service connections elsewhere in ChatGPT have not been exposed to this execution session; this is not a request to recreate tokens/accounts.
3. The website currently enforces **test-only Stripe Checkout and test-only webhook fulfillment**. The supplied six live Price IDs cannot be used with a test key. Existing test-mode counterparts and webhook secrets must be discovered through authorized account access; none were invented or created. Real Stripe test checkout (success/decline/expiry), email delivery, migration reconciliation and hosted admin visibility must pass before any production payment-mode change. This candidate does not enable real customer charges or claim it is a functioning live payment release.
4. Legacy occupied-time reconciliation and production scheduler operation remain unverified. These are required launch gates, not optional post-launch tasks.

The target remains `https://coachtaeqb.com`. Its current deployed commit/health and any new deployment READY state are unverified by this runtime. Local successful tests do not satisfy these external acceptance gates.
