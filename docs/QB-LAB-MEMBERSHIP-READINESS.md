## Remaining product and release gaps

These are implementation gaps, not merely missing credentials:

- No public or real child signup; no approved teen identity model, verified guardian enrollment or owner/admin management UI. All existing minors remain guardian-managed records.
- Existing athlete home, libraries, simulator, progress and coach console still explicitly demonstrate browser-local synthetic histories. **They are not yet fully bound to account-backed progress across modules/devices.** The separate Account workspace persists authorized learning events/tasks; the new inbox persists messages/schedules once connected. Never represent demo history as real account history or silently import it.
- Age/pathway/experience schema support does not certify adaptive curriculum. Coaching-reviewed age prescriptions, seven-on-seven content mapping and personalized recommendations remain incomplete.
- No coach-verified performance workflow, scheduled training calendar editing UI, automatic reminder worker, conversation replies/moderation, account deletion/export workflow or platform-wide owner announcement tool. Schedule revision updates are available in the RPC/API; current UI creates/cancels.
- Group targeting is an explicit recipient snapshot drawn from coach-authorized profiles; no permanent training-group management exists. There is deliberately no unrestricted broadcast bypass. The SQL cap is 100 recipients per transaction; pagination/batching/idempotency keys and operational quotas require review before scale.
- Delivery status means due/available **in the database**, not proof of device notification delivery. Read status is a deliberate recipient acknowledgement, not a tracking pixel. Scheduled messages become readable at due time when the inbox is loaded; no background job is claimed.
- Database audit covers message creation and schedule changes inside their transactions; callers cannot insert, modify or forge audit rows. Authentication/MFA/password auditing must use the provider’s authoritative auth audit stream, which is not connected. A client-callable “record password changed” RPC would permit fabricated events and is deliberately absent. Comprehensive provisioning, consent, export/deletion and operations audit ingestion still requires integration. Audit retention and restricted owner review need approval.
- Distributed application rate limiting, privileged recovery review, provider/SQL integration acceptance, malicious input/concurrency/load testing, media pipeline, full billing tiers/portal/reconciliation and operational backups remain blockers.
- MFA setup secret is returned only to the authenticated bootstrap session and held in component memory; do not screen-share it. It is not persisted by the application. Hosted factor enrollment/cleanup/recovery must be tested before release.
