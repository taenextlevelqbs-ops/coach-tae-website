# Private service boundary — disabled, not a live authentication implementation

The public Preview does not instantiate an authentication/session verifier, database service client, signer or payment provider. `/api/qb-lab/private/*` rejects every supported method with 503/no-store and does not read request bodies. Setting an environment variable cannot silently enable it. The client-only prototype and coach sandbox are openly accessible synthetic tools; they are not authorization controls.

`authorization.ts` is a tested policy kernel and provider interface, not working authentication or a complete upload security implementation. No browser role, imported activity, local consent checkbox or local assignment is trusted by a server. An administrator label alone grants no private athlete/media access. Minor training/media access requires a verified adult relationship and unexpired, unrevoked consent. A verified guardian may request deletion after revocation without regaining read access. Coach access requires an explicit assignment. Family feedback must be released. Quarantined/deleted/expired media cannot be signed.

## External prerequisites and implementation gates

1. Owner-approved region/provider/budget, separate staging project, privacy/retention policy and verified guardian consent process. No service was provisioned or purchased here.
2. Managed adult authentication (proposed Supabase Auth), verified-email/invitation flow and protected adult-age verification. No independent minor signup. Secure HttpOnly/Secure/SameSite session cookies, origin/CSRF validation, recovery, revocation, rate limiting and session rotation must be integrated and tested; the verifier interface does not implement them.
3. The candidate migration has been tested in isolated local PostgreSQL with synthetic auth fixtures. Apply and integration-test it again in an isolated provider staging project. It relies on `auth.uid()` and `auth.users`. Grant creation, adult verification and consent records must use reviewed server workflows; no direct client mutations are allowed by this migration. RLS has not been production certified.
4. A private quarantine bucket and private processed-media bucket; authenticated upload grants bound to account/athlete/object/size, short expiry, concurrency/quota limits. Server MIME/extension/size preflight is only the first filter: magic bytes, real media decode/transcode, malware scan, metadata stripping and limits on duration/resolution are required before release. Signed access is issued only after the policy kernel and DB authorization pass. Never cache signed URLs publicly. No public buckets or real media accepted in this build.
5. Immutable audit/outbox/deletion jobs, immediate revocation behavior, retention manifests, export/delete ownership and backup expiry; test cross-account isolation using real authenticated sessions, storage listing denial, revoked-consent races, interrupted uploads, deletion and restore.
6. Server-only Supabase URL/service credentials, storage signing secret, notification provider and webhook secrets in distinct Preview/production environments. Privileged values never use NEXT_PUBLIC_*. No actual secrets were read, printed or committed. Do not activate real-data routes until the complete integration tests pass.
7. Approved premium products/prices/terms, provider-hosted sandbox checkout and verified/idempotent webhooks. Provider-verified entitlement records—not redirect parameters—authorize features. No checkout or real payments exist here.

The simulator model/engine/rendering split is the extension point for future 3D. A later renderer may consume the same deterministic coordinate/timeline state through an explicit adapter; 2D motion is not a physically validated animation rig. 3D assets, rigging, collision/ball physics, licensed movements and validated coaching curricula are unimplemented.
